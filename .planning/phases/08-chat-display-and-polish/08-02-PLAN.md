2. After the streaming completes for Vision API responses (when imagesToSend was not empty), add quality detection:

```jsx
// After streaming completes, check for image quality issues in response
// Only check if this was an image message
if (imagesToSend && imagesToSend.length > 0) {
  const qualityIndicators = [
    'blurry', 'unclear', 'low resolution', 'hard to see',
    'cannot make out', 'cannot clearly see', 'difficult to read',
    'image quality', 'too dark', 'too bright', 'out of focus',
    'partially visible', 'not visible', 'obscured'
  ];

  // fullResponse is the accumulated assistant response text
  const responseLower = fullResponse.toLowerCase();
  const hasQualityIssue = qualityIndicators.some(
    indicator => responseLower.includes(indicator)
  );

  if (hasQualityIssue) {
    // Use existing imageError display (auto-dismisses after 5 seconds)
    setImageError('Tip: The image quality may affect analysis accuracy. Consider uploading a clearer image if needed.');
  }
}
```

3. The key is to only trigger this check when:
   - The message included images (imagesToSend.length > 0)
   - The streaming has completed (we have the full response)

4. Do NOT trigger for every response - only for image analysis responses.

5. The message should be helpful, not alarming - it's a "tip" not an "error":
   - Use softer language: "Tip: The image quality may affect..."
   - Don't say "error" or "failed"
   - Suggest action: "Consider uploading a clearer image if needed"

Important: Track the imagesToSend state through the async flow. Since handleSend captures imagesToSend at the start, you can check it after streaming completes.
